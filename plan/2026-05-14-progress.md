## 4. Phase 1 — 인프라 (PostgreSQL)

### 구성
```yaml
postgres:
  image: postgres:17
  container_name: gemma-postgres
  ports: ["5432:5432"]
  environment:
    POSTGRES_USER: gemma
    POSTGRES_PASSWORD: gemma
    POSTGRES_DB: gemma
  volumes:
    - "F:/development/gemma-ai-structure/postgres/data:/var/lib/postgresql/data"
  healthcheck: pg_isready -U gemma -d gemma (5s interval)
  restart: unless-stopped
```

```

```

### 파일 구조
```
backend/
├── requirements.txt
└── app/
    ├── __init__.py
    ├── config.py     # pydantic-settings + workspace_dir 절대화
    └── main.py       # FastAPI + /health + /health/llm
```

### 핵심 코드 포인트

**`config.py`** — `WORKSPACE_DIR=./workspace`처럼 상대경로로 들어와도 `PROJECT_ROOT` 기준 절대경로로 정규화:
```python
@field_validator("workspace_dir")
@classmethod
def _resolve_workspace(cls, v: Path) -> Path:
    return v if v.is_absolute() else (PROJECT_ROOT / v).resolve()
```

**`main.py`** — 두 개의 헬스 엔드포인트:
- `GET /health` — 정적 정보 (모델명, base URL)
- `GET /health/llm` — llama-server `/v1/models` 호출해 실연결 확인

### 검증 결과
- `from backend.app.main import app` 임포트 ✅
- uvicorn `127.0.0.1:8000` 부팅 ✅
- `GET /health` → `200 {"status":"ok","llm_base_url":"...","model":"..."}` ✅
- `GET /health/llm` → `200 {"status":"error","detail":"All connection attempts failed"}` ✅ (llama-server 미기동 — 정상)
